Why structural chunks

Insurance PDFs are hierarchical. Packs keep clause boundaries; context at query time uses --window 2 (±2 same-file neighbors by chunk id), not token overlap at index time.

06 · Agent v2

Controller + seed hygiene

Seed = route + catalog + hybrid CE + window. Controller LLM ≤ --agent-max-rounds 2. Then answer LLM (separate call).

Seed hygiene (automatic)

  • File-diverse reorder — first brief page prefers distinct files
  • Unread title map — titles for seed primaries not yet shown
  • Auto page-2 — multi-part / compare questions call more_passages once before first controller turn
  • Early-final deferral — block premature final_answer if multi-part + unread seed remain
  • Lexical nudge — if title/filename token coverage is poor, nudge catalog once
  • Cite hygiene — drop DummyText / OCR junk before answer gen

BRIEF_BATCH=5 primaries shown per brief page. Paging via more_passages does not consume tool-round budget.

07 · Tools

What the controller can call

Champion exposes 6 tools (grep only with --agent-grep — off):

ToolPurpose
peek_titlesScan first-line titles ±radius around a chunk id
fetch_chunksLoad up to 4 chunk ids into working passages
catalog_lookupSearch product/file catalog when seed looks wrong
searchAnother hybrid retrieve+rerank; optional catalog narrow
more_passagesNext brief page of seed · free vs round budget
final_answerStop gathering · trigger answer LLM
Mental model: agent improves use of a strong seed; it is not the primary search engine. Prefer paging unread seed over burning rounds on search.

09 · Verify (measured)

LLM sentence-level extras trim

After the answer is written, code splits it into units S1…Sn (paragraphs/sentences; caveat tails like שים לב: get their own unit). Kimi-K3 returns which unit ids to drop — only ancillary / unasked content. Safety net reverts if the ask would break.

Results (postprocess on frozen champion answers):
  • Train-48Q: 87.5% → 91.7% OK · fully_supported 100% · fixed extras 41/43/46
  • Eval-61Q: 82.0% → 83.6% OK · GT 88.5% → 90.2% · 0 regressions
  • Verify call: ~1.4–1.6s mean when it runs (gate skips short answers)
(same family as answer)

EnvRAG_VERIFY=1

v1 Gemma “strip unsupported” regressed to 68.8% — do not use that. Scripts: run_verify_llm_postprocess_48q.sh / _61q.sh.

14 · Staff FAQ

Questions you should be able to answer

Does the agent search the whole corpus from scratch?
No. Dense+CE builds a strong seed first. The agent mostly pages, peeks, fetches, and occasionally re-searches. Max 2 tool rounds.
Why both MiniLM and BGE?
MiniLM cheaply ranks 100 candidates; BGE re-ranks the top 40 more accurately. Offline GT recall peaks with this order + top-k 25.
Why not filter hard by domain?
Misroutes caused refusals. 80 from routed domains + 20 global keeps cross-domain gold without discarding the router.
Are FAQs deleted?
No — still in the index. They are excluded at retrieve time because scraped FAQs are mostly question titles without answers.
Where do citations come from?
Answer body has no paths. Footer USED_PASSAGES: 1,3 maps indices to passage file+page. Cite hygiene drops OCR junk before generation.
Is verify part of production?
Recommended opt-in. LLM verify (Kimi, extras mode) lifted Train 87.5%→91.7% and Eval 82%→83.6% with ~+1.5s. Enable with --verify or RAG_VERIFY=1. Old Gemma strip-to-68% is dead — do not use.
Why is latency ~25–45s?
Roughly three equal buckets on Train: cross-encoder retrieve (~7s), agent tool loop (~8s), answer LLM (~7s). Route ~1.5s. Verify adds ~1.5s when it runs.
Why is grep off?
Measured regressions on full 48Q (controller burned rounds / bad queries). Lexical catalog nudge remains without grep.
Chunk size?
Structural packs toward 500 tokens, hard max 700. No index-time sliding overlap; neighbors via window=2 at retrieve.
How are tables handled?
Dual representation: short NL description for embedding/CE; full CSV in payload for the answer model.
What can still fail?
Gold pages never in seed (~15% offline full-group miss), OCR/DummyText forms, unasked extras (fully_supported), underspecified branching questions.
